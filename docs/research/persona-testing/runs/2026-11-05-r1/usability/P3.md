## Bennett/NSGC issues seen
- Genetic test result shown as gene only on the symbol, with the result moved to the Key (K7). Bennett places the test and result under the individual.
- Age at death "60s" lost, so the drawing claims more precision than the history has (K1).
- New siblings always go to the right, so birth order is wrong unless fixed by hand (K8; standards doc §"Left-to-right birth order").
- Two conditions default to the same quarter. If left alone, the key would show two identical patterns (S2 risk).
- Unknown-zygosity twins render correctly ("?" at a single point) once found.
- Not wrong, but noisy: the partner picker offers MZ/DZ, and the co-twin does not copy its twin's sex.

## Extension task notes
- **Where is the data stored?** Answered within seconds by on-screen copy ("Saved locally", "Your work is saved only in this browser", shield tooltip "None of your data leaves your device", help footer). Helen believes the claim, but nothing in the app is a document she could give IT: there is no privacy page and no list of storage mechanisms, retention, or what happens on logout.
- **Close the tab and reopen:** all 14 people, names, notes, conditions, the investigation and the Key came back unchanged, with no prompt. On a personal machine that is good. On a shared clinic PC with a shared browser profile, it shows identifiable patient data to the next user. There is no visible "clear this pedigree / sign out / close patient" action and no warning about it (H6 relevant: whether the profile is wiped at logout decides whether this is a privacy issue or a data-loss issue).
- ☰ → Open goes straight to a file picker. There is one implicit working document, so Helen cannot tell whether earlier patients' pedigrees also linger.

## Deviations
- Driven with Playwright Chromium, not Edge. Same viewport (1920 x 1080, DSF 1).
- Typing went through `keyboard.type` and `fill` into fields located by placeholder or visible text. The twin zygosity dropdown was set with `selectOption`, because Playwright cannot click native `<option>` elements. A human would pick it from the dropdown, with the same KLM cost.
- The first attempt to scroll to "Unknown zygosity" with `scrollIntoViewIfNeeded` timed out (the option sits inside a native select). This is a driving problem, not an app problem; Helen scrolled the panel with the wheel instead.
- Downloads were captured with Playwright's download event. The PDF was checked by rasterising it with pdftoppm, and the PED file by reading its text.
- Clicking the shield icon may be meant only as a tooltip. This is recorded as "no further info", not as a defect.
- "About Pedigree Canvas" opened a second tab. Both tabs were closed before the reopen test, inside the same browser context.
