## Bennett/NSGC issues seen
- **Test result not on the symbol** (§11 says the investigation result is a short identifier under the symbol, e.g. "BRCA1 +"). The canvas and PDF show "BRCA2" alone; the result is moved into the Key. A reader can take this for a positive result.
- **Generation numerals missing from the PDF** (§10 says Roman numerals go on the left margin). They are shown on the canvas but dropped in the export.
- **Birth order** (§13.2, left to right): new siblings are always added to the right regardless of age, and the wand reformat re-sorts without regard to age (brother back to the right; affected aunt moved from 2nd to 3rd place). Manual drag is the only fix.
- **Age at death "60s"** cannot be entered; Age is integer-only, so the uncertain age becomes a precise "d. 60". The §11 `?` convention for an uncertain diagnosis has to be typed by hand in a note; Cause of Death is stored but never drawn.
- Correct and good to see: unknown-zygosity twins drawn as a single point with "?" (§8); the proband arrow points to the lower left with "P" (§7); the deceased slash; quadrant shading with an automatic key.

## Extension task notes
- **Pen vs app, by step** (KLM vs paper estimate [A]):
  - Structure (14 symbols + lines): app ≈ 40 clicks ≈ 60–70 s with M; paper ≈ 60–90 s. **App faster**, and layout and renumbering are automatic.
  - Annotations (ages, d., 3 cancers with dx ages, VUS, "stomach trouble"): app ≈ 2.5 min (condition + separate note + onset box per cancer, panel scrolling); paper ≈ 1–1.5 min. **App 2× slower.** This is where H1 is lost.
  - Twins with "?": paper ≈ 3 s; app ≈ 15–25 s first time (hidden Shift-click route).
  - Fixing a mistake (brother's birth order): paper = redraw (minutes); app = one drag (≈2 s). **App far faster.** This answers frustration 1, "impossible to update".
  - Export for EHR: paper = walk to the scanner; app = 2 clicks, but the result is 20.8 MB.
- **Paper import (E31):** none. Import is PED only (lossy, structure only). The command palette has no photo/scan/image command, and help says nothing. A paper-to-digital route would need either image import with tracing, or a quick-entry mode fast enough that retyping old pedigrees is bearable.
- Privacy: the shield pop-over ("nothing is ever sent to a server") directly answers his manager question (E18). The open question is whether a hospital would allow browser-local storage of identifiable data on a shared clinic PC (he typed an MRN into the title).

## Deviations (Playwright-driving issues, not app problems)
- Edge is not available, so this was run in Chromium headless at 1366×768. Font rendering may differ slightly from Edge on Windows.
- The repo's local `node_modules/playwright` did not match the installed browser build, so the global Playwright install (`/opt/node22/lib/node_modules/playwright`) was used. The browser stayed in one long-lived session the whole time.
- Hovering the wand icon showed no tooltip in the screenshot. Native `title` tooltips do not render in headless screenshots, so a human on Edge may see a label that the persona did not. The "unlabelled wand" finding is therefore uncertain.
- The first command-palette attempt failed because the locator text "Command palette..." did not match the menu's ellipsis character; it was clicked by position instead. This is not an app issue.
- Keystrokes were typed by script, not by hand. Typing errors a real user would make are not modelled; the KLM times assume error-free entry.
- The PDF was checked by rasterising it with `pdftoppm` rather than opening it in a viewer.
