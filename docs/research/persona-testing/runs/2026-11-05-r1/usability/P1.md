## Bennett/NSGC issues seen
- **Investigation result not under the symbol** (§11 expects e.g. "BRCA1 +" beside the individual). "BRCA2" alone, with the result in the Key, is non-standard and clinically ambiguous.
- **Cause of death not rendered**, although the reference lists `causeOfDeath` among sub-symbol annotations (§11).
- **Approximate ages ("60s", "~60") can't be entered** as age or age at death.
- **The PDF has no generation numerals.** The canvas has them, but the referral PDF loses individual identifiers such as III-3.
- Twin "?" placement: correct single point + "?" (§8), though the glyph overlaps the descent line.
- Reviewer flag (not an app bug): the app's **DZ** rendering draws both twins from one apex with no bar. That matches the published NSGC figure, in which MZ and DZ both share one point and MZ adds a bar. But `docs/bennett-pedigree-standards.md` §8 and the answer key's wording ("not DZ separate points") describe DZ as "separate points". The repo doc and the answer key should be checked against the 2008/2022 figure.
- Deceased slash direction, proband arrow position, quarter shading with legend, and partnership/sibship lines all match.

## Extension task notes
- **CanRisk:** not possible. There is no CanRisk/BOADICEA export or import, and no mention in help or ⌘K. The `.ped` export holds only family ID, UUID individual IDs, parent IDs, sex and a status column, with no ages, cancer diagnoses, ages at diagnosis, genetic test results or proband flag. That is the data CanRisk needs, so Priya still re-enters the family. Evidence E23 stands.
- **PDF for referral letter:** achievable. Document details (author, institution, reference condition) and a renamed title appear in the PDF header, which partly addresses E27. Missing: a logo/letterhead upload, a vector or compact file (20.8 MB), generation numerals, and a local date format (11/5/2026 is ambiguous in Australia).
- The extension took ≈1.3 min KLM, including one help lookup.

## Deviations (driving via Playwright, not app problems)
- Browser state did not persist across separate Playwright runs (the app's storage is not captured by `storageState`). The fix was one long-lived browser fed step scripts, so there was no effect on the persona flow.
- The native `<select>` for zygosity was set with `selectOption` by its visible label. A human would click and choose; KLM counts it as two point-clicks.
- Hover buttons and panel fields were clicked by screen coordinates read from screenshots. KLM counts a point for every hover.
- ⌘K was sent as Meta+K on Linux Chromium; it opened the palette as on a Mac.
- The PED file was inspected as text, which assumes Priya opens it in a text editor.
- **Answer-key exposure:** the protocol file was read in full before drawing, so the answer key was visible up front. This may have made the agent more alert to sibling age order than a naive tester. The persona card's standards literacy (high) would produce the same checks.
- The Bennett reference doc was read only after drawing, for scoring.
