## Bennett/NSGC issues seen
- **Unknown zygosity** (§8): Raj did not reach it. The popup offers only MZ/DZ, and DZ without "?" asserts dizygotic. A Zygosity control does exist in the panel once twins exist (found by P1), so this is about discoverability, not capability.
- **Birth order left to right** (§12.2): not kept on insertion (brother, cousin). It is not consistently restored by Reformat either: an early Reformat by P1 flipped Sarah's children.
- **Lines do not cross / symbols uniform and distinct** (§12.4): a new partner was drawn overlapping an existing person (E1). Two sibships shared one line (E2). A consanguinity line ran through other people (E3). The engine fixed all of these on a later action, but not reliably on the first.
- **Generation numbering** (§10): correct on the canvas and updated as generations are added, but **missing from the PDF**. Individual numbers are reassigned on relayout, which breaks the `II-3` reference format as a stable identifier.
- **Consanguinity** (§5 table): double line rendered correctly once laid out. There was no prompt for degree of relationship, and the key has no line for it.
- **Genetic test notation**: the result belongs on the symbol, not only in the key (answer key K7).
- **Half-sibs / multiple partners**: the final rendering is correct (the father has two partnership lines and the half-sib drops from the second union).

## Deviations (Playwright-driving, not app problems)
- The repo's local `playwright` package expects browser build 1228, which isn't installed. The runner used the global Playwright 1.63 (`/opt/node22/lib/node_modules`) with the preinstalled Chromium 1243. No install was done.
- The Alt-drag was synthesised as Alt keydown + mouse down + 20 interpolated moves + mouse up. A human drag would be similar. Hover handles needed an explicit mouse move before clicking, which a human does naturally.
- Clicks in the properties panel used fixed coordinates read from screenshots. The panel layout shifts as conditions or notes are added, so each step was re-screenshotted before clicking. No mis-clicks affected the outcome.
- ⌘K was sent as Control+K (Linux). The palette opened, so this is equivalent.
- KLM counts are reconstructed from the step scripts, so the action totals are approximate (±10%).
- The documented "Mark selected as twins" command (`docs/bennett-pedigree-standards.md`, read only after the test) presumably needs two people selected. The persona searched ⌘K with one person selected. That is recorded as a discoverability finding, not a driving error.
